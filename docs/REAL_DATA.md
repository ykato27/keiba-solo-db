# 実データの取得（Phase 4 前倒し）

keiba-solo-db の検証基盤（evaluation/）は、もともと合成データ中心の
`data/keiba.db` で動作確認をしていた。本書は、実データを取得して
学習・評価できるようにするための取得経路・手順・注意点をまとめる。

## 取得元

**JRA公式英語データサービス「JRA Race Card & Results」**
- 入口: https://japanracing.jp/en/ （JRAの英語ポータル）の
  "JRA Race Card & Results" リンク先 https://jra.jp/JRAEN/AP/common/main
- 内容: JRA公式のレース結果。全着順、枠番・馬番、性齢、斤量、
  確定オッズ（単勝）、人気、着差、コーナー順位、騎手・調教師、
  および払戻（PAY-OFF: 単勝・複勝・枠連・馬連・ワイド・馬単・
  三連複・三連単、100円あたり金額）。
- 位置づけ: 日本中央競馬会（JRA）自身が一般公開している公式情報。
  本プロジェクトでは個人の研究目的で、後述の礼儀を守って取得する。
  再配布はしない（取得したDBは手元での学習・評価にのみ使う）。

### 採用しなかった経路と理由

| 経路 | 結果 |
|---|---|
| www.jra.go.jp（日本語公式サイト。旧 scraper/ が想定した `/keiba/result/{race_id}/` 形式のURL） | そのURL形式は実在しない。加えて本環境からはトップページ自体が HTTP 403 を返すため中止（403/429 では中止する方針） |
| netkeiba のスクレイピング | 利用規約上のリスクが指摘されているため主経路にしない |
| Kaggle の takamotoki「JRA Horse Racing」データセット | 出所は netkeiba のスクレイピング。ダウンロードには Kaggle アカウントが必要で、本環境からは取得不可（API が 404）。上記の出所の問題もあるため不採用 |
| JRA-VAN（JV-Data） | 公式だが有料契約・専用ソフトが必要で対象外 |
| GitHub / Hugging Face 上の公開データセット | JRA の結果＋オッズ＋払戻を備え、ライセンスが明示されたものは見つからなかった（2026-10-23 調査） |

## 取得の礼儀（実装済み）

- リクエスト間隔は既定6秒（10件/分、リポジトリ既存の
  `scraper/rate_limit.py` の方針に合わせた）。`--interval` で変更可。
- User-Agent を明示する（`keiba-solo-db/1.0 (personal research; ...)`）。
- HTTP 403 / 429 が返ったら、その時点で取得全体を中止する。
- サーバーが一時的に返すエラーページ（HTTP 200 の "SYSTEM ERROR"）や
  タイムアウトは、レース単位で間隔を空けて最大3回まで再試行し、
  ダメならそのレースだけをスキップして件数を報告する。
- 1レースごとにコミットするため、中断しても再実行で続きから進める
  （取り込み済みレースはスキップ）。

## 実行方法

```bash
# 開催日を指定して取得（YYYYMMDD、カンマ区切り）
uv run python scripts/fetch_jraen_results.py \
    --dates 20250112,20250119,20250209,20250216

# 取り込んだ実データで評価（レポートは evaluation/reports/ へ）
uv run python -m evaluation.run_comparison_real
```

- 保存先は `data/keiba_real.db`（本番 `data/keiba.db` とは分離）。
  スキーマは `sql/schema.sql` と同一＋払戻テーブル `payouts`
  （race_id × 券種 × 組合せ → 100円あたり払戻）と `import_meta`。
- 取得メタ情報は `data/keiba_real.meta.json` に残る。

## 初回取得の結果（2026-10-23、正直な記録）

- 当初計画: 2025年1〜6月から各月2日、計12開催日
  （20250112, 20250119, 20250209, 20250216, 20250309, 20250322,
  20250412, 20250420, 20250511, 20250524, 20250614, 20250622）。
- 実際の取り込み: **2025-01-12 の2レースのみ**（中山11R・中京11R、
  出走34件、払戻24件）。パース・取り込み・払戻整合性チェック
  （単勝の組合せ=勝ち馬、複勝は3着以内）はすべて正常だった。
- 中止の経緯: 取得を進めるうちサーバーが一時エラーページ
  （HTTP 200 の "SYSTEM ERROR"）を返すようになり、最終的に
  **HTTP 403** が返ったため、本書の方針どおり取得元を中止した。
  短時間にセッションを繰り返したことがブロックの引き金になった
  可能性が高い。
- このため、実データでのウォークフォワード評価
  （`evaluation/run_comparison_real.py`）は**まだ実行できていない**
  （2レースでは時系列分割が成立しない）。評価ランナー自体は
  実装済みで、データが揃えばそのまま実行できる。
- 再開方法: 時間を空けるか別のネットワークから、同じコマンドを
  再実行するだけ。取り込み済みレースはスキップされ、続きから
  進む。再開時はセッション回数を抑えるため、1回の実行を
  1開催日以内に留めることを推奨する。
- 評価が成立する目安: 最低でも5開催日以上（時系列分割のため）、
  本格的には数十開催日・数千レース規模。

## 実データ側の制約（正直な申告）

- **馬体重が無い**: JRAEN の結果ページに馬体重の掲載がないため、
  `race_entries.horse_weight` は NULL（特徴量では 0 埋めになる）。
- **前走間隔は取得範囲内のみ**: `days_since_last_race` は取り込んだ
  レース同士で計算するため、範囲の序盤や初出走では過小／NULLになる。
  範囲を広げるほど改善する。
- **馬・騎手・調教師は英語名**で登録される（JRAEN の表記のため）。
  本番DB（日本語名）とは別DBなので混ざらない。
- **完走しなかった馬**（競走中止等）は、結果表の着順が序数で
  表現されない場合、取り込み時にスキップされ件数が報告される。
- 本格評価に必要な量の目安: 検証フォールドあたり数百レースは
  欲しいため、数十開催日・数千レース規模まで広げることが望ましい。
  初回範囲は「パイプラインが実データで回ることの確認」が目的。
